# CFB 2026 team metrics

This project was handed off from a Claude chat on 2026-11-22. In that chat the user asked for a series of
college football splits and rankings, which were computed, checked and delivered as an Excel workbook.
The goal now is to **build a website that presents this information**.

Nothing about the site is decided yet: stack, design, hosting, which pages come first, and whether it is
public. Ask before choosing. Read `docs/conversation-summary.md` first for what the user asked for and how
they reacted, then `docs/methodology.md` for how each number is defined and what was verified.

## Snapshot

- Games through Saturday 2026-11-21: 822 completed regular-season games, 138 FBS teams, 11 games each for
  the power-conference teams.
- AP poll of 2026-11-22 (13 polls so far, preseason included; 41 teams ranked at least once).
- CFP committee ranking of 2026-11-17 (next release 2026-11-24). It predates the Nov 21 games.
- 247Sports Team Talent Composite as last updated 2026-08-28 (a preseason roster-talent ranking).

`data/json/meta.json` carries these as-of values. Read them from there rather than hard-coding them.

## Layout

- `data/json/*.json`, `data/csv/*.csv`: site-ready tables, same content in both formats.
  `docs/data-dictionary.md` describes every column and is generated by the build.
  - `team_summary`: one row per FBS team with everything. Start here.
  - `top50`, `home_away_splits`, `games`, `ap_polls`, `ap_receiving_votes`, `cfp_rankings`.
  - `upcoming`: unplayed games with the model's projected spread (SRS gap + fitted home edge). Label it a
    projection from this site's model, never a betting line.
- `data/cfb_2026_team_metrics.xlsx`: the workbook delivered in chat. Same numbers; not regenerated by the build.
- `data/raw/`: feeds downloaded by `pipeline/fetch_raw.sh`. `data/manual/`: hand-entered reference values.
  `data/derived/`: cached per-game game-control numbers.
- `pipeline/`: `build.py` regenerates every table; `ratings.py` and `game_control.py` hold the two models;
  `schema.py` holds column descriptions.
- `docs/metric-ideas.md`: other metrics discussed but not built.
- `data/box/<game_id>.json`: one box score per completed game 2020-2026 (linescore, team stats, player stats) for the
  site's game pages, built by `pipeline/boxscores.py` from ESPN's team_box/player_box tables in cfbfastR-cfb-data.
  Defensive player stats are sparse before 2023 in that feed; 2020 time of possession is blank for ~18% of games.
- `data/players/<athlete id % 500>.json`: every player's season totals and game logs (same script), sharded so a
  player page loads one file. Season totals sum counting stats and recompute averages; QBR is not totalled.
- `data/history/`: past seasons 2020-2025 (`team_seasons`, `games`, `meta.json`) built by `pipeline/history.py`
  for the team pages. Raw feeds go to `data/raw/history/` (git-ignored, ~330 MB); per-game game control is cached in
  `data/derived/history/`. `data/manual/talent_247_history.txt` holds 247's composite order for each past season.

## Commands

```bash
pip install -r pipeline/requirements.txt
python pipeline/build.py        # rebuild tables from data/raw + data/manual
bash pipeline/fetch_raw.sh      # refresh feeds (needs git; play-by-play is about 55 MB), then rebuild
bash pipeline/fetch_history.sh  # past-season feeds (once); python pipeline/history.py rebuilds data/history
bash pipeline/fetch_box.sh 2026 # box score feeds (data/raw/box, git-ignored); python pipeline/boxscores.py writes data/box and data/players
node ../fpl-dashboard/scripts/cfb-export.mjs   # copy everything into the site (public/data/cfb)
```

The build runs without the play-by-play file by using the cache in `data/derived/`. It stops with a clear
error if a computed record disagrees with the standings feed, and warns when a hand-entered file is stale.

## Definitions the site must keep straight

- **AP ranked / unranked**: an opponent counts as ranked if it appeared in *any* 2026 AP Top 25, preseason
  through the latest poll, no matter where it stood on game day. This is not "ranked at kickoff". FCS
  opponents count as unranked.
- **Ranked in the latest poll** (`vs_cur_ranked_*`, `opp_cur_rank`): opponent ranked in the most recent poll, AP or
  CFP, whichever was released last (by the release dates in `published.json`; `meta.json` `latest_poll` says which).
  Past seasons use the final post-bowl AP poll. Like the AP split, it applies to every game against that opponent.
- **Talent tiers**: opponent's 247Sports talent rank, 1-25, 26-50, 51+. FCS opponents fall in 51+.
  `talent_tier` is stored as 1, 2, 3.
- **Top 50**: ranks 1-25 are the AP Top 25; the next ranks are the other teams receiving AP votes, by
  points; the rest are filled by this project's model. Rows with basis `Projected` are an estimate, not a
  published ranking, and must be labelled that way wherever they appear.
- **Game control**: share of regulation time leading, tied and trailing; average lead across regulation;
  margin with garbage time removed (lead of 38+ in Q2, 28+ in Q3, 22+ in Q4). Overtime counts toward
  margins but not toward time shares.
- **Home / away / neutral**: neutral-site games are their own split so a team's rows add up to its totals.
- **Team set**: the user asked for "Power 5 + Notre Dame". That was read as the four power conferences plus
  Notre Dame, with the eight-team 2026 Pac-12 included and labelled. `in_power_set` marks those 76 teams;
  the tables cover all 138 FBS teams.

## Rules for presenting the data

- Show as-of dates near any ranking or record. The three sources have different dates.
- Never present the model's projected ranks, `model_rank` or `model_score` as official.
- Keep "ranked at least once this season" wording for the AP split. Shortening it to "vs ranked teams"
  invites the wrong reading.
- Records are strings like `10-1` only for display. The data stores wins and losses as numbers.
- The user read most of the chat on a phone, where wide tables were a problem. Check mobile layouts early.

## Refreshing after new games or polls

1. `bash pipeline/fetch_raw.sh`
2. Update `data/manual/`: `ap_receiving_votes.csv` (teams outside the Top 25 with votes are not in any
   feed) and the reference lists and dates in `published.json`.
3. `python pipeline/build.py` and read its warnings.

## Past seasons

- Postseason games count in past seasons (not in the current one until it ends). "AP-ranked at least once" spans
  all of that season's AP polls including the final one.
- The `cfb_team_talent` table in cfbfastR-cfb-data is **not** the 247 composite (it puts UCLA 61st in 2026 where 247
  has 25th). Past talent ranks come from 247's own pages, read in a browser: 247 blocks scripted requests with a
  JavaScript challenge, so curl gets nothing.
- The raw 2022 schedule lacks weeks 3 and 12; `history.py` fills missing games from `cfb_schedules` plus `linescores`.

## Before publishing

- Logos in `team_summary` are ESPN-hosted and the marks belong to the schools. Confirm with the user before
  using them on a public site.
- If the site will be public, check the terms for republishing ESPN-derived data, AP poll results and the
  247Sports ranking, and credit the sources on the site.
